## Гурван сценарио

### 1. Performance сценарио

| Хэсэг                  | Тодорхойлолт                                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Тойм**               | Хэвийн хэрэглэгчийн ачааллын үед `/cart/add` endpoint нь хурдан хариу өгч, хэрэглэгчийн сагсанд бараа нэмэх үйлдлийг саатуулахгүй байх. |
| **Системийн төлөв**    | Сервер хэвийн ажиллаж, `/cart/add` endpoint хүсэлт хүлээн авах боломжтой байна.                                                         |
| **Орчны төлөв**        | Орчн хэвийн, стандарт сүлжээний холболт                                                                                                 |
| **Гадаад өдөөлт**      | Хэрэглэгч сагсанд бараа нэмэх үйлдэл хийж `/cart/add` endpoint рүү хүсэлт илгээнэ.                                                      |
| **Шаардлагатай хариу** | Систем хүсэлтийг амжилттай боловсруулж, сагсанд барааг нэмэн HTTP амжилттай хариу буцаана.                                              |
| **Хэмжүүр**            | `/cart/add` endpoint-ийн response latency **p95 < 4 ms**, **p99 < 40 ms** байна.                                                        |

### 3. Availability сценарио

| Хэсэг                  | Тодорхойлолт                                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Тойм**               | Сервер гэнэт crash болсон үед систем автоматаар дахин асаж, үйлчилгээг богино хугацаанд сэргээх.                                          |
| **Системийн төлөв**    | Сервер хэвийн ажиллаж, хэрэглэгчийн хүсэлтүүдийг боловсруулж байна.                                                                       |
| **Орчны төлөв**        | Орчн хэвийн, стандарт сүлжээний холболт                                                                                                   |
| **Гадаад өдөөлт**      | **ЭВДРЭЛ (crash):** сервер гэнэт зогсоно.                                                                                                 |
| **Шаардлагатай хариу** | Сервер автоматаар дахин асаж, үйлчилгээг сэргээн хэрэглэгчийн хүсэлтийг дахин боловсруулах боломжтой болно.                               |
| **Хэмжүүр**            | Бүх хүсэлтийн амжилтын хувь **p95 ≥ 95%**, **p99 ≥ 90%** байх ба серверийн сэргэх хугацаа **p95 ≤ 10 секунд**, **p99 ≤ 15 секунд** байна. |

### Алхам 2-ын өөрийн шалгалт

- **Итгэмжтэй:** Бодит хэрэглэгчийн үйлдэл болон бодит системийн эвдрэлийг өдөөлт болгон тодорхойлсон.
- **Үнэ цэнэтэй:** Хариу өгөх хугацаа, төлбөрийн алдаа, системийн зогсолт зэрэг хэрэглэгчид шууд нөлөөлөх үзүүлэлтүүдийг хэмжинэ.
- **Тодорхой:** VU, хүсэлт/секунд, туршилтын хугацаа болон эвдрэлийн хугацааг тодорхой заасан.
- **Нарийн:** Endpoint, өдөөлт, хүлээгдэж буй хариу болон хэмжүүр бүрийг тусад нь тодорхойлсон.
- **Ойлгомжтой:** Бүх сценарио ижил 6 хэсэгтэй бүтэцтэй бөгөөд хэмжүүрүүд нь тоон босготой.

## Сценарио бүрээс SLO гаргах

| Сценарио         | SLI (юуг хэмжих)            | Босго               | Цонх / нөхцөл                                        |
| ---------------- | --------------------------- | ------------------- | ---------------------------------------------------- |
| **Performance**  | `/cart/add` latency         | **p95 < 4 ms**      | **20 VU** тогтмол ачаалалд, **1 минут**              |
| **Reliability**  | `/pay` error rate           | **< 8%**            | **20 VU**, **1 минут**                               |
| **Availability** | Бүх хүсэлтийн амжилтын хувь | **p95 ≥ 95%**       | **10 VU**, **2 минут**, **10 секундийн crash** орсон |
| **Availability** | Сэргэх хугацаа              | **p95 ≤ 10 секунд** | **10 секундийн crash**-ийн дараах recovery           |

### SLO босго сонгосон шалтгаан

`/cart/add` endpoint-ийн **p95 < 4 ms** босгыг хэрэглэгчийн сагсанд бараа нэмэх үйлдэлд мэдэгдэхүйц саатал үүсгэхгүй байх зорилгоор сонгосон. `/pay` endpoint-ийн **8%-ийн error rate** босгыг туршилтын үед бага хэмжээний төлбөрийн алдаа гарах боломжийг тооцож, хэт хатуу бус боловч найдвартай ажиллагааг шалгах зорилгоор сонгосон. Availability-ийн **90%** босго нь 10 секундийн crash-ийг 2 минутын туршилтын цонхонд багтаан системийн recovery-г шалгах боломж олгоно.

### Availability Error Budget

Availability SLO:

**90%**

Туршилтын цонх:

**2 минут = 120 секунд**

Тиймээс зөвшөөрөгдөх downtime:

**120 × (1 − 0.90) = 12 секунд**

Иймээс availability-ийн **time-based error budget = 12 секунд** байна.

Энэ нь туршилтын 2 минутын цонхонд систем нийтдээ **12 секунд хүртэл** unavailable байхыг SLO зөвшөөрч байна гэсэн үг.

Алхам 5-д үүнийг хүсэлтийн тоонд шилжүүлж тооцно. Цаг хугацаагаар тооцсон **12 секунд** болон хүсэлтээр тооцсон error budget хоёр өөр тоо гарах боломжтой. Учир нь эхнийх нь систем **хэдэн секунд unavailable байсныг**, харин хоёр дахь нь **нийт хүсэлтээс хэд нь амжилтгүй болсныг** хэмждэг.
